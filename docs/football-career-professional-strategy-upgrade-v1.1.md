## 0. 升级全貌

只解决一个问题：**职业一线队的半年策略，应直接影响本窗口的比赛机会与风险，并让玩家理解实际执行的效果。**

保留三种选择、半年一次的决策节奏、现有角色和比赛模拟框架，不增加玩家操作层级。

| 策略 | 玩家应理解的收益 | 玩家应理解的代价 |
|---|---|---|
| PUSH：主动争取出场 | 本半年更积极争取出场与首发 | 身体负担增加，通常承担更高伤病风险 |
| STEADY：先站稳脚跟 | 改善竞技、身体准备状态，降低风险 | 不额外提高出场和首发区间 |
| TEAM_FIRST：先服从球队安排 | 更容易被灵活使用，改善更衣室关系和心理状态 | 首发占比倾向下降，更多机会可能来自替补 |

“通常”“倾向”有明确含义：受角色上限、状态上下限、伤病和取整影响，不保证每个种子都多踢、少首发或产生不同结果。恢复优先时，以上策略效果不执行。

工作按四阶段推进：**规则与基线 → 引擎与平衡 → 报告与兼容 → 连续体验与发布验收**。前三阶段分别形成一次实现交付，第四阶段集中体验验收；WP 工作包是检查清单，不要求各自单独交付。

## 2. 已核对的问题与实施范围

### 2.1 当前实现

当前 `simulateProfessionalHalfYear.ts` 中：

1. `prepareProfessionalWindow()` 先处理恢复或策略准备效果。
2. `simulateFirstTeamStats()` 按输入角色的固定区间生成出场、首发；策略未作为显式修正传入。
3. 比赛结束后才评估并逐级调整角色，作用于下一窗口。

因此，PUSH 目前虽然改变教练关系、身体状态和训练投入，却没有直接提高本窗口的出场、首发区间。当前策略并非完全没有即时效果：身体、竞技、心理状态仍可间接影响比赛表现和伤病，不能把旧版描述为“三种选择结果完全相同”。

### 2.2 本次允许修改

- 职业一线队的策略配置与准备效果。
- 本窗口出场区间、首发区间、伤病概率的策略修正。
- 恢复优先时的新修正禁用与旧规则兼容。
- 一线队策略说明、必要的青年队文案分支及报告说明。
- 对应测试、基线、平衡观察、兼容与页面验证、实施记录。

### 2.3 本次不修改的规则

青训前两年、职业青年队模拟、青年队晋升、`firstTeamProgress`、转会和海外资格、合同谈判、属性成长公式、年龄成长与衰退曲线、国家队、荣誉、职业事件、`evaluateFirstTeamRole()` 权重与阈值、俱乐部参数、角色等级、18场半年赛程、随机种子命名体系。

本次不新增存档字段或迁移，维持 SAVE / DATA 12 / 12。若实施证明确需改变存档结构，应先形成原因和兼容方案交统筹处理，不能默默扩大范围。

**外围规则不变，不代表外围输出不变。** 比赛时间和表现变化可以通过现有公式影响成长、声望、后续角色、国家队、荣誉和市场结果。必须解释这种正常传导，并检查异常；不能为了复现旧输出强行抵消新策略收益，也不能借此改动外围规则。

本次不启动队徽、页面重设计、事件扩写、关键比赛操作或新的角色互动系统。

## 4. 比赛公式与不变量

### 4.1 角色基础区间保持不变

| 角色 | 出场比例区间 | 已出场比赛中的首发比例区间 |
|---|---|---|
| FRINGE | 0.05～0.20 | 0～0.10 |
| SUBSTITUTE | 0.20～0.40 | 0.15～0.35 |
| ROTATION | 0.40～0.65 | 0.45～0.65 |
| STARTER | 0.65～0.90 | 0.75～0.90 |
| CORE | 0.80～0.95 | 0.85～0.95 |

策略只修正当前角色区间，不能临时提升角色，也不能改下一窗口角色评估公式。

### 4.2 出场、首发修正

```ts
appearanceMinAdjusted = clamp(appearanceMin + appearanceRateBonus, 0, 0.98)
appearanceMaxAdjusted = clamp(appearanceMax + appearanceRateBonus, appearanceMinAdjusted, 0.98)
startMinAdjusted = clamp(startMin + startRateBonus, 0, 1)
startMaxAdjusted = clamp(startMax + startRateBonus, startMinAdjusted, 1)
```

仍按原流程抽取比例、应用伤病可用率并取整。不要在结果上直接执行 `appearances += 2`，也不要额外重抽随机数。

**允许取整后出场18场。** `18 × 0.98 = 17.64`，四舍五入为18；0.98不构成“必定休息一场”的承诺。本次不另加17场硬上限。

始终保证：`0 <= starts <= appearances <= 18`，分钟数非负，评分沿用现有边界。保留现有角色最低出场约束，不因策略另设保底场数。

### 4.3 伤病公式

非恢复的一线队策略执行时，候选公式为：

```ts
baseInjuryRisk = 0.04
  + (50 - preparedPlayer.fitness) * 0.001
  + (45 - preparedPlayer.attributes.physical) * 0.0005

injuryRisk = clamp(baseInjuryRisk + injuryRiskDelta, 0.015, 0.16)
```

`preparedPlayer` 是完成策略准备及现有维护后的比赛输入，不能使用界面选择前的身体状态代替。

恢复模式沿用旧伤病规则：同一基础公式、无策略修正、截断 **0.03～0.12**。恢复模式不得统一套用新截断，否则即使三个修正都为零，仍会改变受保护路径的行为。

现有伤病时长、可用率和随机命名空间保留。新风险上下限和“恢复使用旧范围”均须集中定义并有边界测试，不散落魔法数字。

### 4.4 不再使用统一伤病差值验收

默认参数下，身体状态50、身体能力45、无维护、非恢复时：

- PUSH：准备后身体46，风险6.9%。
- STEADY：准备后身体52，风险2.3%。
- 差值为4.6个百分点，不是 V1.0 预期的1.5～3.5个百分点。

这些是公式核算，不是完整引擎试跑证据。高状态、高身体能力时，两种策略还可能同时落在概率下限，风险差值为零。

验收应核对具体输入的理论概率和抽样发生率，不强求所有输入都出现固定差值；同一起点正常策略间的风险方向原则上应为 PUSH ≥ TEAM_FIRST ≥ STEADY，截断导致相等必须解释。若实际交互产生反向结果，记录反例交统筹判断。

## 5. 执行顺序、恢复与默认策略

### 5.1 唯一恢复判定时点

保持当前业务顺序：

```text
已选计划 / 已发生的本期事件
→ 处理本期到期后果
→ 进入职业模拟，取得策略准备前的球员状态
→ 按 form < 46 或 fitness < 46 或 morale < 46 判定一次恢复
→ 执行恢复或策略准备
→ 执行现有训练维护
→ 按最终准备状态模拟比赛
→ 成长、状态、角色、合同及外围结算
→ 持久保存报告和历史
```

低于46触发，等于46不触发。不能在 PUSH 扣身体状态之后或维护结束后再次判定恢复，也不能仅凭选计划页面的预判决定最终执行。

返回明确的内部执行信息，如 `recovery`、`effectiveApproach`、`matchModifiers`；恢复为 true 时，三个比赛修正均为0，且不执行任何策略准备奖励或成本。

恢复支持沿用旧规则：只为低项增加竞技7、身体10、心理8；不叠加维护收益、成本和衰退减缓。新改造应复用此判断，不新增另一套阈值。

注意：现有 `TrainingExecution` 在年轻球员路径可能为 null，不能只靠它判断是否恢复。采用策略准备函数返回的明确结果，覆盖全部一线队年龄。

当前赛后队内关系分支也使用 `!trainingExecution?.recovery` 判断 TEAM_FIRST 的额外收益，年轻一线队恢复时存在继续取得这项奖励的可能。S1应冻结一个对应反例；S2将本次策略专属的赛后判断一并对齐明确的恢复结果。恢复时正常比赛表现带来的关系变化仍可执行。此处如与旧数值不同，作为有证据的恢复一致性修正单独列明，不宣称恢复路径所有字段都与旧版完全一致。

### 5.2 空策略与旧存档

当前准备函数的空策略会进入 STEADY 分支。新版保留此语义：合法旧档 `developmentApproach: null` 在非恢复的一线队结算时按有效策略 STEADY 执行；不把缺省值变成无奖励的第四种选择。

恢复模式优先于空策略回退。内部有效策略可用于报告，不强行改写旧档已存在的历史选择值。非法枚举仍由现有校验拒绝，不能宽松降级掩盖损坏。

旧的未结算计划加载后按新版本规则继续；已生成报告、荣誉、历史不重算、不补写。保持“同版本、同输入、同种子、同策略可复现”，不承诺升级前后相同输入的未来结果完全相同。

### 5.3 随机性与角色边界

保留现有随机命名空间、抽取结构和窗口标识，不添加 `Math.random()`，不为不同策略换种子以制造差异。不要承诺不同策略的每个输出字段都保持随机轨迹一致：参数变化可能自然影响现有随机算法的后续消耗。

合同兑现仍按实际生成本期比赛的球队层级和角色结算，不能用窗口结束后的晋升角色倒算。22岁强制进入一线队等既有资格规则继续有效；测试以引擎实际进入的球队分支为准。

### 6.2 青年队隔离与选择页面

当前 `TrainingPlanScreen.tsx` 的 `professionalApproaches` 同时用于职业一线队和职业青年队。必须依据实际球队层级区分文案：

- 职业青年队：保留原机制对应的说明，不能复用新增比赛概率承诺。

一线队候选短文案：

| 策略 | effect 候选 |
|---|---|
| PUSH | 争取更多出场与首发 · 身体负担增加 |
| STEADY | 改善竞技与身体状态 · 降低伤病风险 |
| TEAM_FIRST | 更多灵活出场机会 · 首发占比倾向下降 |

说明文字补充风险和关系收益；最终用词在参数冻结后定稿。主界面不暴露内部百分比，不扩大策略按钮体积，不增加必须阅读的新卡片。低状态一线队须明确“最终恢复优先时由恢复安排接替策略”，不能只有老将看得到保护说明。

### 6.3 半年报告

新策略说明必须写入 **`eventSummary`**，继续与 `trainingEventSummary()` 兼容。`hints` 可辅助提示，但不能承担唯一说明；合同处理会截取 hints，依赖它会丢失归因。

报告按本次实际执行生成并随原报告保存，不在回看时读取当前选择或新配置重新拼接。

| 实际情况 | 报告要求 |
|---|---|
| 正常执行 | 写明有效策略、本期提高或降低了哪些倾向、准备收益与成本 |
| 恢复优先 | 写明策略未执行，由恢复安排接替；不得同时声称额外出场或风险减免已生效 |
| 关系 / 状态饱和 | 不宣称取得了被截断的完整奖励；可简短提示已受上限限制 |
| 比例或风险触及上下限 | 不承诺完整名义增益或必然存在策略间风险差异 |
| 旧报告 | 原样读取，不补造新版说明 |

归因描述限于真实执行的规则，例如“本期提高了争取出场和首发的倾向”。没有反事实模拟，不写“因此多踢了2场”“这次伤病由主动争取造成”。没有实际方差证据，不写“保证状态稳定”。

解释应短、可读，并与已有维护说明区分；检查事件、合同、国家队等报告拼接后仍能看到，不覆盖原信息。无需新增玩家必须点击的确认。

## 7. 验证设计与分角色验收

### 7.1 基线与比较口径

至少保留三组：旧版同策略结果、新版同策略结果、新版三策略配对结果。每次对比固定完整输入，仅改变被比较的策略或版本。

不要通过重新生成球员、俱乐部或选择不同种子制造差异。种子清单、起点状态、代码版本、配置、脚本和聚合口径一并保留；构造输入明确标注，不称真实匿名存档。

已有冻结样本只读，新证据另建目录。旧测试中的“输出必须与旧版完全一致”如受本次授权规则改变影响，应逐条解释后改为新断言；保留原输出，不能批量刷新快照掩盖变化。未改的青年队、恢复的准备和比赛公式保留相应旧数值回归；第5.1节策略奖励残留的修正及报告新增说明单独核对，不扩大为其他恢复数值改动。

### 7.2 固定状态的主矩阵

基础矩阵：5角色 × 3策略 × 100固定种子 = 1500次一线队模拟。冻结一份合法一线队起点，控制年龄、状态、能力、位置、俱乐部、训练、合同和事件输入；角色变化仅用于受控测试，不称自然生涯分布。

主矩阵建议使用正常非恢复状态、常规训练和未饱和关系；第一阶段记录具体值。另单列边界矩阵，不能把恢复、高状态和正常样本混成一个均值。

输出每角色、每策略的均值和分位数，至少包括：出场、首发、替补出场、分钟数、平均评分、伤病、准备及最终状态、关系、成长、声望、roleAfter。首发占比采用 `sum(starts) / sum(appearances)`；总出场为零则记 N/A，不记0冒充比较。

### 7.3 角色分层标准

| 角色 | PUSH 对 STEADY | TEAM_FIRST 对 STEADY |
|---|---|---|
| FRINGE | 平均出场提高；首发允许出现从0到少量的变化，不强求+0.7场 | 出场 / 替补机会提高；原本首发为0时不要求继续减少 |
| SUBSTITUTE | 平均出场、首发提高 | 重点检查替补次数增加、首发占比下降；不设固定首发减少场数 |
| ROTATION | 主要感知样本：平均出场增加以1.2～2.2场为首轮观察目标；首发应提高 | 平均出场小幅增加，替补次数增加、首发占比下降 |
| STARTER | 出场和首发提高，允许接近上限时收益收敛 | 检查使用结构变化及关系收益，不要求固定减少场数 |
| CORE | 允许上限压缩增益，不套用 ROTATION 的最低场数要求 | 检查首发占比、替补次数及上限影响，不承诺每个种子都更有利 |

首轮观察目标不是最终平衡证明。第二阶段依据冻结输入锁定可重复的验收阈值；未达到目标时先检查公式、截断、伤病和输入，再判断是否调参，不得直接放宽断言。

角色仍是主因：正常控制样本下，`STARTER + STEADY` 平均出场应比 `FRINGE + PUSH` 至少多4场，并检查五角色整体排序。相邻角色允许原有区间重叠，不要求每个种子严格排序。

### 7.4 伤病验证

- 单独冻结至少1000个种子，三策略共享种子；每个重点状态组分别统计，不与1500次主矩阵混算样本数。
- 覆盖一般状态、临界非恢复、高身体 / 高状态、恢复、老将维护。记录实际准备状态及公式计算概率。
- 用概率公式边界测试保证计算正确，用样本发生率验证实现没有漏接或额外抽样；不要靠小样本发生率证明百分点精度。
- 当预期差值很小或发生率排序不明确时，使用预先确定的更大样本（建议10000）或报告不确定性，不挑选“好看”的种子。
- 恢复下三策略修正必须完全禁用，并与旧风险公式匹配；正常高状态可因下限而相等，不能假称强弱必然不同。

### 7.5 连续窗口观察

从至少三个固定起点各分出三条策略分支，连续观察3～5个半年：年轻轮换、成熟主力 / 核心、34岁以上老将。每个起点三分支同种子、同训练及其他选择规则，仅策略不同；起点不同不得称配对。

老将至少覆盖身体维护与另一种合法维护计划，检查“PUSH + 身体维护”是否抵消了全部实质代价。同步统计：累计出场、分钟、伤病及周数、身体状态轨迹、恢复窗口数、成长、声望、角色、关系及关键合同结果。

后续市场或事件因新结果发生分歧时，使用预先说明的共同选择政策，记录首次分歧；不能强行把后续状态改回相同。角色变化、伤病、恢复均作为真实结果保留。

样本只能排查明显失衡，不能证明所有生涯都不存在最优策略。若 PUSH 在机会、成长、声望上持续占优且无明显代价，或 TEAM_FIRST 只有损失而关系很快饱和，应回到第二阶段处理，不先用文案包装。

### 7.6 必测边界与兼容

- 三策略各自重复运行完全相同；不修改输入对象；出场、首发、分钟和评分满足不变量。
- 三项状态分别为45、46、47；事件 / 到期后果跨阈值；PUSH 自身扣分后低于46但本次不二次恢复。
- 30 / 31 / 34岁维护分界、高状态截断、老将身体维护；不改变已有维护收益、成本和减衰退规则。
- 空策略按 STEADY；青年队不执行新修正；22岁强制一线队的既有分流正常。
- 旧档覆盖计划、事件待选 / 结果、待模拟、已生成报告、市场 / 谈判、退休等合法阶段；加载、合法下一动作、保存和重载。
- 旧报告及历史内容保持不变；新报告保存重载后保留策略说明；回看报告不重新结算。
- 合同兑现不提前使用新角色；荣誉不重复计数；国家队、市场等沿用现有规则，区分合理连带变化与回归缺陷。
- 保留 v11 迁移和备份相关保护；不能只因当前版本不变就跳过旧档恢复验证。
