## 1. 三分钟了解全貌

### 1.1 目标与用户收益

保留“13 岁起步、每半年做选择、自动模拟、最终形成退役档案”的轻量游戏，修复选择失效、职业路线受限和重复确认三个问题。

| 优先级／工作包 | 当前问题 | 本次要达到的行为 | 复杂度控制 |
| --- | --- | --- | --- |
| 1／T 老将训练 | 31 岁后身体不再正常成长；34 岁后五种普通训练可能产生完全相同结果，页面仍提示成长 | 玩家看到适龄、有效且有取舍的训练计划；报告说明维护或衰退的原因 | 复用四项能力、三项状态和现有年龄曲线；不增设老将属性体系 |
| 2／M 转会方向 | 常规成人报价将部分留洋偏好变成国内球队的硬排除条件 | 海外球员可改变求职方向，回国等合理路线可达；报价保持稳定 | 复用职业偏好与现有市场窗口；不做自由搜索全部球队或无限刷新市场 |
| 3／F 半年流程 | 看完报告后还需经过重复展示相同数据的结束页 | 普通窗口一次操作进入下一半年；关键合同、转会、退役仍有明确入口 | 先合并呈现和入口，保留必要的底层状态兼容，不重写全站导航 |

**执行顺序：S0 基线与方案 → T 训练 → M 转会 → F 流程 → Q 综合验收 → R 授权发布。**

先锁定三个专项的接口和存档约定，再逐项开发。T、M、F 都可能触及 `gameStore.ts`、页面和存档，默认串行落地，避免并发覆盖。

### 1.2 完成的含义

- 开发完成：代码、定向测试、变更说明齐备。
- 专项验收通过：对应规则、真实页面和存档场景有证据。
- 升级可交付：三个专项及综合验收通过，文档与实际行为一致，用户完成最终验收。
- 发布完成：另有明确发布授权，并完成指定远端与线上核验。

上述状态分别记录。规划完成不代表方案已获批准；测试通过不代表发布完成。

## 2. 范围与约束

### 2.1 本次包含

1. 适龄训练选项、实际效果、相关解释文案与回归验证。
2. 成人市场资格筛选、报价组合、偏好修改入口及防重抽规则。
3. 半年报告和结束页的入口整合、条件分流、旧流程状态恢复。
4. 必要的存档兼容、完整生涯回归、桌面／移动端验证和产品文档同步。

### 2.2 本次不包含

- 完整阵容、真实赛程、逐场比赛、动态升降级、新增位置或新经济系统。
- 扩充俱乐部库、批量制作队徽、全站视觉改版、主题重做。
- 为了“更好玩”顺便重调所有成长、伤病、国家队和荣誉概率。
- 多存档槽、账号云存档或全局事件系统重构。

专项如确实需要越过上述范围，先记录原因、替代方案和成本，由用户决定；不混入常规修复。

### 2.3 技术与体验边界

- 固定种子继续可复现；已经生成的事件、报价和报告不因刷新被重抽或重算。
- 新规则可影响升级后的未来窗口；旧报告、历史数据、已确定报价不得追溯改写。
- “相同版本、种子和完整选择序列得到相同结果”是确定性要求；跨版本未来数值完全相同不是本次承诺。
- 优先复用现有状态。新增枚举或字段时，要写清必要性、默认值、迁移路径和存档版本影响。
- 常规外部报价继续最多三份；合同到期时续约报价是否另计，按现有模型核对并在 D-M2 写清，不误删必要的续约入口。
- 保持每半年少量有意义的决策；新增偏好入口不变成每半年必填步骤。
- 涉及共享界面时同步验收移动端；仅针对桌面的样式调整不得改变移动端呈现。
- 保护已有工作区改动和用户本机存档；测试使用隔离数据，不覆盖用户生涯。

## 6. 三个专项的实施与验收要求

### 6.1 T：让老将训练有效且能理解

**动作拆分**

1. 画出训练焦点、职业策略、强制恢复、特殊事件、成长／衰退的执行顺序，检查同一状态是否被多次奖励。
2. 用现有数据实现分龄方案，避免只是将“成长”改名为“维护”，引擎却没有对应效果。
3. 适龄选项与默认选项一起调整，旧存档中已选 `physical` 等枚举能被可靠解释，不因界面移除而卡住。
4. 报告使用实际计算结果说明收益；有随机性时不承诺某一次比赛必然改善。

**验收用例 T-A**

- 覆盖 30→31、33→34、36→37 岁边界和接近退役阶段；覆盖身体／心理低状态、属性接近潜力上限。
- 覆盖 ST、CM、CB 的代表性能力结构，避免只对一种位置有效。
- 同种子、同球员的成对比较验证每个选项的真实作用及代价；再以一组固定种子确认总体方向，不能拿不同天赋球员之间的差异证明训练收益。
- 保留选项在适用条件下有预期差异；到达上限而无收益时，界面提示原因或限制无效选择。
- 维护不能消除年龄衰退，也不能通过恢复叠加无限增加状态；具体上限在 D-T2 锁定。
- 年轻阶段若没有获批规则修改，应通过同输入前后对照确认保持既有行为。
- 报告、计划和存档恢复中的术语一致；不泄露原本隐藏的潜力数值。

### 6.2 M：可改变方向，但不能靠刷新刷报价

**动作拆分**

1. 资格层：分清法律／年龄／合同等必要约束与产品偏好筛选；先修复常规市场对国内路线的硬排除。
2. 组合层：明确常规三份外部报价、到期续约与救济报价各自组成；让有条件的候选产生不同选择价值。
3. 抽取层：在合格组合内使用固定随机流和权重；候选不足时使用确定的回退顺序，不编造不合格报价。
4. 偏好入口：明确当前方向、何时生效和是否已有报价；持久化规则与按钮行为一起完成。

**验收用例 M-A**

- OVR 79／80／84／85，CONDITIONAL／STRONG／DOMESTIC，国内／海外效力及至少青年、成熟、老将阶段。
- 常规市场、合同到期续约／自由转会、豪门低出场救济分别覆盖。
- “回国可达”先验证合适国内球队能进入资格池，再验证组合能够选到；不要求无论条件如何每轮必出国内报价。
- 更新偏好前后在相同种子与条件下对照，检查方向影响；至少保留 100 个固定种子的抽样记录，阈值在 D-M2 定义，不能看完结果再定标准。
- 报价不重复、不含当前俱乐部的外部邀请；候选不足和极端偏好有明确行为；原有续约不被三份上限误删。
- 已生成报价在刷新、往返导航、连续修改偏好、保存／读档后内容和谈判结果不变；尚未生成的下一市场使用新偏好。
- 不追溯改写开局档案和已记录的职业选择；明确历史字段与当前偏好的展示来源。

### 6.3 F：合并重复页面，保留所有必要决定

**动作拆分**

1. 盘点旧结束页的所有能力：下一半年、市场、合同到期、失约转会、留队、复查报告、退役、退出国家队。
2. 为每类状态决定报告末尾的主按钮和次要入口，复用统一判断，避免页面条件与 store 条件冲突。
3. 普通窗口一次操作进入下一计划；其他窗口直达相应决策流程。旧 `PRO_STAGE_COMPLETE` 存档通过兼容入口继续。
4. 验证阶段变更不会再次模拟、重复发薪、重复记录比赛、事件或荣誉；更新对旧页面结构有依赖的自动驾驶测试。

**验收用例 F-A**

| 场景 | 必须保留的结果 |
| --- | --- |
| 正常窗口，无需处理市场／合同 | 报告后一次操作进入下一计划；窗口只前进一次 |
| 已有正式报价 | 能直接查看报价并按现有约定作去留选择 |
| 合同到期 | 先完成续约或新合同，不能直接跳到训练 |
| 连续失约 | 申请转会与允许的继续留队均可达 |
| 自愿退役／强制退役 | 保留确认、原因和正确年龄；不得越过最终窗口继续签约 |
| 可退出国家队 | 入口仍可达，原有不可撤回确认保留 |
| 回看旧报告／来回切导航 | 只读，不推进时间、不重结算 |
| 刷新、双击、连续触发按钮 | 无重复推进、重复收入、重复历史或中间状态死路 |
| 旧报告／旧结束页／特殊事件结果存档 | 能继续；待处理事件和合同不被跳过 |

以“看到报告后至下一项实质决定需要几次主动操作”计算步骤，记录同场景前后对照。普通窗口至少减少一次必经确认；不把减少必要确认当作收益。
