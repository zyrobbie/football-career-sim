## 1. 服务硬协议（D-02/03/04/11/12）

1. 九档原价和数值不变：身体2000/10000/40000，一期身体状态+2/+4/+8；心理2000/10000/40000，两期每期心理状态+1/+2/+4；安顿10000/20000/60000，三期每期心理状态+1/+2/+4、队内关系+1/+2/+3。一次全额支付，不续费、不手动领取、无装备或能力奖励。
2. 年龄用现有 playerAgeAtWindow；18+、有 current contract 且 remainingHalfYears>0、HALF_YEAR_PLAN且没有报告回顾/退休确认/在途事件时可买。成年青年队职业合同纳入；未成年不买。年度统一 startYear+floor(windowIndex/2)。当年任一可编辑计划可补做，每年最多一份，取消面板不占额度。
3. 购买窗口W即第一期待结算窗口；W..W+N-1冻结。不立即改player，不提前派发全部增益；跨年自动继续不占下一年额度。
4. 同类任何未执行期存在时不重购、不升档、不重置。不同类跨年可重叠。每个目标统一上限85，实际增益=max(0,min(名义增益,85-当前值))；高于85的原值不降低。先按购买窗口，再按稳定购买序号/ID逐项分配实际值；例如80、旧安顿+4、新心理+4=>安顿4、心理1。上限是本轮保留候选，需80/85/90小矩阵证明后定案，未经记录不得改九档承诺。
5. 当前身体一期预演为0时禁止购买。心理/安顿不能因当前饱和就禁止，因为未来可能受益；只在可证明全程无可经历窗口等情形拒售。支付前显示当前可预估实际值、全部理论总量、饱和风险、已知最大可经历期数及中断退款规则。
6. 合同到期不等于立即退休；若正常续约/转会后职业继续，心理支持继续。无职业模拟的阶段不凭空发一期；若此游戏确有可连续推进的失业半年，则在提交该半年时按“无职业窗口”终止尚未执行服务并退款，不把日程偷偷后移。当前流程无这种职业空窗时无需新增系统。

## 2. 单一准备、凭据、财务

准确顺序：现有已选择事件结果及到期后果 → 原始年龄/球队规范化 → 原恢复与职业策略判定 → 原训练维护 → 本期个人安排纯准备 → 原模拟/关键时刻 → 结算报告与执行凭据一起持久化。付费增益不得回头取消任一状态<46所触发的恢复优先，不补做此前被取消的PUSH等策略。成年青年队也必须有且仅有一次服务准备入口。

准备函数输入不可变，返回 adjustedPlayer、每份安排每目标的planned/actual/reason、拟结算receipt。允许关键时刻创建、验证、结果预览多次调用，所有调用均不消费期数/不退款/不写故事。receipt键=`careerIdentity:arrangementId:windowIndex`，含承诺规则版本、实际目标数值和截断理由。最终报告一次事务提交；若同键已存在则保持原状态，不重发。UI只读同份receipt，不另算收益。报告区分计划、实际付费贡献、原始半年净变化。

付款ID绑定 careerSeed+player.id+purchaseYear+window+类型+档位+稳定序号；quote还绑定现金、当年额度、当前计划和服务状态摘要。Store在执行前重验最新状态，过期确认拒绝并显示新报价。付款、余额、年度占用、冻结日程和购买账目一次save后才更新内存/提示成功。无localStorage必须失败，不接受saveGame旧的无存储静默成功分支。写成功但回读异常属于结果未知：禁止直接再扣，应先读取当前档查同ID；已存在则恢复已购状态，否则才允许重试。双击、旧闭包、换档后旧确认均测试。

V3支付/退款ledger为现金独立条目，至少id、window、arrangementId、kind、amount、reason。购买当期记支出一次，后续期不重复记价；退款发生窗口记收入一次，退休发生时在退休摘要显示。原现金字段保持唯一余额来源，不维护第二份可消费余额。服务执行不构成现金收入。

退款：中断时所有尚未执行期标TERMINATED，不再可执行。目标比例退款为floor(priceEuro * terminatedCount / totalPeriods)，本次只补足该目标与已退差额。服务终态若所有已执行目标实际均为0（包括0期执行即取消），追加refund使累计恰等于原价，绝不再退第二份全款。部分有收益不退已执行期，即使其中其他期为0。每个退款事件有稳定键；任何路径退款总额<=price，现金不能负数。例：60000安顿执行1期有效后搬城=>40000；执行1期全0后搬城=>比例40000再无效补足20000，共60000。10000安顿只剩1期终止=>3333（不是3334）。

年度名额返还仅限购买同游戏年、0期已执行、全额取消；执行过全0也不返还，跨年退款不返还旧年或赠本年。一次搬城资格即使取消也不重新复制，避免取消刷资格；可用同一资格重新买仅当原购买0执行且全额取消、资格仍在原两窗口内并且年度名额依法恢复，不能新增moveId。

## 3. 城市/搬家（D-13）

选择稳定的“俱乐部游戏生活主城”抽象，不宣称球员真实住所，不把比赛场地/公司地址自动等同城市。334真实队参考已查来源；对多城/城市边界采用明确表中产品选择。32中国队按现有虚构世界作者设定PRODUCT_CANON，不声称真实俱乐部或现实来源。完整366条核准表及说明在同目录 approved-city-map.json；来源研究原文件不改写。40别名必须先resolveClubParametersId，406 accepted IDs同结果，未知返回null。未来改映射不能凭数据升级触发搬城。

关键例外：Manchester United/City同gb_manchester；Anderlecht/Union同be_brussels，均为明确足球生活圈产品例外，不把所有都市圈普遍合并。London按已有London键；Watford不并London、West Bromwich不并Birmingham、Avellaneda/维多利亚不并Buenos Aires。多主场日本按核准表固定主基地，不随比赛场地变化；FC Tokyo=jp_chofu、Tokyo Verdy=jp_inagi。Gangwon=kr_gangneung，FC Andorra=ad_andorra_la_vella，均标PRODUCT_HOME_BASE并保留多城事实，不宣称独一官方城市。其余29边界建议逐条以来源支持的原suggestedCityId批准，除上述明确覆盖项。

初始化：第一次选队/旧档迁移只设currentCity，不生成搬家。当前有来源的known A→known B且A!=B的实际转会签约提交才生成move；同城换队/续约/国家队/旧记录初始化均不生成。unknown→known仅初始化，known→unknown置unknown并撤销无法继续证明的当次购买资格，unknown→unknown不生成。不得越过unknown间隔拿更早known推断搬城。

真正搬城提交与原城市安顿终止退款原子保存，心理继续。再次搬城生成新的moveId，从该转会后的第一个HALF_YEAR_PLAN算可编辑窗口1；第二个连续可编辑计划窗口仍可买，第三个过期。通常即moveWindow和moveWindow+1；迁移冻结过程不消耗不存在的计划访问，使用语义上的计划窗口而非打开次数。记录moveId、origin/destinationCityId、from/to canonicalClubId、window、source=TRANSFER_COMMIT；一份安顿绑定此moveId。

unknown目的地：因无法确认是否仍在原城，停止旧安顿未执行期并按“居住城市无法核实”退款；不生成新安顿资格。不得默认为真实搬家；该处理是服务条件不可核实而非搬家判断。
