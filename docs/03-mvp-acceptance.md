# 绿茵生涯：最小 Demo 与验收标准

版本：0.6
目标：交付一个简单、直接、可玩、可可靠读档的青训前两年、首份职业合同，以及可以在职业半年和国内转会窗口之间持续推进的生涯闭环。

## 1. Demo完整流程

```text
首页
→ 基础身份
→ 位置
→ 职业追求
→ 留洋偏好
→ 球员生成
→ 三份青训邀请
→ 入队事件
→ 半年发展计划
→ 特殊事件（按窗口条件出现）
→ 青年队半年模拟
→ 半年报告
→ 冬季半年发展计划
→ 青年队第二次半年模拟
→ 第二份半年报告
→ 第二年职业策略与训练选择
→ 第三、第四次半年模拟与报告
→ 15岁一线队晋升评估
→ 首份职业合同
→ 接受原报价或进行一次反报价
→ 签约并写入球队层级、角色承诺和合同状态
→ 首个职业半年
→ 转会机会评估
→ 表现未达标时直接进入下一职业半年
→ 每隔2至3个窗口且表现达标时生成最多三份报价
→ 留队或完成一次转会谈判
→ 新援融入事件
→ 新俱乐部职业半年
→ 后续职业半年继续按相同规则评估
→ 自动存档
→ 关闭网页
→ 继续生涯并恢复到正确阶段
```

## 2. P0功能

- 新建生涯；
- 继续生涯；
- 删除生涯二次确认；
- 当前年份读取；
- 固定13岁中国球员身份；
- 偏好球衣号码与惯用脚；
- 主位置和相邻副位置；
- 四项职业追求排序；
- 留洋倾向和最多三个偏好联赛；
- 按既定概率生成初始综合能力；
- 生成符合位置形状的四项能力；
- 生成并隐藏四项潜力；
- 锁定生涯随机种子；
- 生成三份有明显取舍的青训邀请；
- 选择青训俱乐部；
- 首次入队事件；
- 51个教练、队内、比赛、媒体、健康、合同、国家队与职业里程碑特殊事件；
- 每个特殊事件阶段提供2至3个有取舍的选项；
- 同一事件组按各自冷却期阻止重复；
- 当前合格事件按本局出现次数分层，出现次数最少的一层等概率抽取；存在未经历事件时不得重复抽取已出现的常驻事件；
- 队长、导师、关键比赛责任等事件按年龄、实际队伍层级、实际角色、连续履历与关系联合校验；
- 一窗口延迟后果及报告说明；
- 连续四次半年发展选择；
- 第二年每个窗口选择一项职业策略；
- 青年队角色、出场、首发、分钟、进球、助攻和评分；
- 半年成长；
- 状态和关系变化；
- 青训津贴与现金；
- 首半年伤病保护；
- 低状态时的俱乐部恢复支持；
- 四份连续半年报告；
- 可解释的一线队关注度、培养准备、比赛证明和教练推荐；
- 观察名单、跟训候选、跟训与正式晋升结果；
- 根据实际晋升结果生成青年队或一线队首份职业合同；
- 年薪、年限、角色、解约金和俱乐部选项；
- 更高工资、更高角色或更低解约金的一次反报价；
- 首份合同反报价失败时保留原报价；
- 首个职业半年比赛、成长、工资和合同兑现；
- 每隔2至3个窗口进行一次表现驱动的转会机会评估；
- 机会出现时生成最多三份国内转会报价及一次反报价；
- 转会签约、关系重置与新援融入；
- 转会后继续职业半年，并正确结算新俱乐部成绩、工资和合同；
- 每次进入新转会窗口时重新生成报价，不复用上一窗口数据；
- 自动存档；
- 内部备份；
- 刷新后恢复；
- 同一种子与选择产生同一结果。

## 3. Demo不包含

- 完整成年队赛季；
- 海外俱乐部数据库；
- 全量海外转会市场（当前扩展版已完成24家代表性俱乐部的第一批闭环）；
- 完整国家队赛程、对手与阵容数据库（当前扩展版已完成中国成年国家队的轻量征召、比赛数据与大赛结果闭环）；
- 跨窗口伤病、治疗与康复系统；
- 完整联赛、杯赛和洲际赛事；
- 市场价值页面；
- 个人奖项；
- 标签；
- 退役结局；
- 云存档和账号。

这些模块的数据字段可以存在，但不能以不可操作的空页面出现在Demo中。

## 4. 三份青训邀请

每次必须生成三种不同取舍：

| 类型 | 训练条件 | 竞争 | 预计角色 | 一线队路径 |
|---|---|---|---|---|
| 豪门 | 优秀 | 激烈 | 多为轮换 | 较难 |
| 中型 | 良好 | 正常 | 轮换或主力 | 正常 |
| 小型 | 普通 | 较弱 | 主力或核心 | 较快 |

验收条件：

- 不允许三家俱乐部的设施、青训和预计角色完全相同；
- 预计角色必须来自真实选拔公式；
- 俱乐部展示信息不泄露隐藏潜力；
- 返回上一步不能刷新三份邀请；
- 重新读取存档不能刷新邀请。

## 5. 首个半年保护

- 最严重只允许当窗结算的轻微短期伤病；
- 不允许解约；
- 不允许强制退役；
- 不允许长期无队；
- 单次事件后关系不得跌破35；
- 不允许能力异常暴涨；
- 低表现仍然可以造成竞技、心理和角色方面的合理后果。

首半年保护只由`windowIndex === 0`决定。第二个窗口使用独立随机流，
首次入队事件的关系与训练奖励不得重复结算。

### 特殊事件闭环

- 首个青年队窗口不叠加特殊事件，避免与首次入队事件重复；
- 第二个窗口必须能够稳定触发特殊事件，用于验收完整链路；
- 其他窗口按固定种子、阶段和球员状态确定性抽取；
- 同一窗口最多一个特殊事件，三个选项必须同屏横排；
- 付费选项不能透支，且不得成为统一最优解；
- 刷新并继续生涯后，未选择事件的标题与选项保持不变；
- 结果写入本窗口报告，延迟后果写入下一窗口报告；
- 390×844视口下，事件主体不超过半屏且页面无横向滚动。

事件系统扩充阶段还必须满足：普通窗口长期统计触发率为68%至72%；六种互动外观共用两套结算协议；俱乐部内剧情状态在转会后重置；版本1至10存档均可迁移到版本11；健康事件不得创建跨窗口伤病或康复状态。

## 6. 半年报告

报告主信息必须包含：

- 起止窗口；
- 俱乐部和青年队；
- 角色；
- 出场、首发、进球、助攻和平均评分；
- 四项能力前后变化；
- 有明显变化的状态与关系；
- 青训津贴、事件支出和当前现金；
- 一至三条有真实条件依据的下阶段提示；
- 一线队关注度及三项来源的前后变化；
- 自动保存状态。

内部能力有进展但显示整数未变化时，必须提示接近下一等级，不能让玩家误以为成长系统没有运行。

## 7. 业务不变量

每次生成、选择、模拟、存档和读档后都检查：

- 能力、潜力、状态和关系为有限数字；
- 能力、状态和关系位于0至100；
- 潜力不低于当前能力；
- 综合能力位于合理范围；
- 主位置熟练度100；
- 初始副位置熟练度92；
- 现金为非负整数；
- 出场、首发、分钟和比赛数据不为负；
- 首发不超过出场；
- 青年队数据不进入成年职业总计；
- 当前俱乐部ID存在；
- 游戏阶段与待处理事件一致；
- 已确认模拟的随机输入完整；
- 最近事件最多6项；
- 长期承诺最多5项。

任何不变量失败时停止写入新存档，并保留上一份合法存档。

### 当前扩展：成年国家队

- 只有进入俱乐部一线队且年满16岁的球员参与中国成年国家队选拔；
- 选拔统一使用位置综合能力、竞技状态、俱乐部半年评分、俱乐部平台、知名度和健康情况；
- 中国队游戏性加成只参与世界杯、亚洲杯结果，不参与入选判断；
- 同一种子与窗口产生相同的征召、角色、出场和赛事结果；
- 国家队出场、进球、助攻与首秀窗口写入版本10存档，并在主界面、半年报告和退役档案显示；
- 30岁后可不可逆退出国家队，不影响俱乐部生涯；
- 不增加逐场赛程、对手、国家队阵容和独立国家队页面。

## 8. 单元测试

### 身份

- 球衣号码1至99边界；
- 球衣号码非法格式；
- 左脚、右脚选择写入球员档案；
- 旧版出生年月存档自动迁移。

### 综合能力与生成

- 各位置权重合计100%；
- 初始OVR概率表合计100%；
- 初始能力校准到目标OVR；
- ST进攻至少比防守高12；
- CB防守至少比进攻高15；
- 各位置属性不超出允许范围；
- 潜力层级概率表合计100%；
- 四项潜力与位置目标相匹配；
- 10,000次生成不出现`NaN`或越界。

### 成长

- 潜力差为0时不成长；
- 不能突破潜力和99；
- 重点训练获得固定训练份额；
- 平衡训练不设置单项重点；
- 状态和训练质量正确进入发展指数；
- 相同种子输出一致。

### 财务

- 累进可支配收入在各档位边界连续；
- 半年收入等于年度可支配收入的一半；
- 青训津贴全部进入现金；
- 现金不足不能选择付费选项；
- 达到储备上限后不增加超额现金；
- 降薪不扣除已有现金。

### 存档

- 合法存档往返序列化结果一致；
- 非法主存档能够恢复内部备份；
- 未知更高版本被拒绝；
- 旧版本迁移后通过校验；
- 待选择事件刷新后保持不变；
- `SIMULATION_READY`刷新后得到相同半年报告。

## 9. 批量模拟

至少运行10,000个首半年样本，输出：

- 初始综合能力频率；
- 五档隐藏潜力频率；
- 各位置四项能力均值、最小值和最大值；
- 三类青训邀请的选择差异；
- 青年队角色分布；
- 出场、首发和分钟分布；
- 各位置进球、助攻和评分分布；
- 四项成长均值与极端值；
- 三项状态变化；
- 轻微伤病比例；
- 现金变化；
- 不变量失败数量。

最低要求：

- 不变量失败数为0；
- 概率分布在合理统计误差内；
- 不出现负数、空值、无穷值或异常大数；
- 首半年不会普遍获得超过合理范围的整数能力增长；
- 豪门、中型和小型邀请均有可解释的选择价值。

## 10. 页面与无障碍

- 375px宽手机无横向滚动；
- 1440px桌面不出现过度拉伸；
- 所有按钮有明显悬停、聚焦、选中和禁用状态；
- 键盘可以完成建档和事件选择；
- 表单错误与字段建立语义关联；
- 颜色不是唯一状态提示；
- 支持`prefers-reduced-motion`；
- 正文和关键控件达到可读对比度；
- 浏览器刷新不会丢失已经确认的步骤。

## 12. 完成定义

只有同时满足以下条件，Demo才能标记为完成：

- P0流程全部可用；
- 构建、类型检查和单元测试通过；
- 10,000次批量模拟不变量失败为0；
- 桌面和手机完整走通一次；
- 在事件页刷新后能够正确恢复；
- 半年结算后刷新，报告完全一致；
- 主存档损坏测试能够恢复内部备份；
- 浏览器控制台没有未处理异常；
- 视觉实现与已确认视觉概念完成逐项截图对比；
- 没有用占位按钮或假数据冒充已完成模块。
