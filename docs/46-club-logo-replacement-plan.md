## 5. 每个联赛怎样实施

1. **冻结输入。** 检查源 SHA 与映射，备份本联赛旧资源和清单。记录无关的已有工作区改动，不覆盖或清理。
2. **技术预检。** 确认 SVG 不依赖网络图片／字体、没有脚本或事件处理器，检查内嵌位图、滤镜、裁剪和遮罩能否被浏览器及导出器处理。发现问题具体定位到文件；XML 可解析只算其中一项。
3. **做 4 枚样板。** 沿用文件名和现有组件，先试旧资产替换与原短标升级为图片两条路径。不能只复制 public 文件而遗漏清单；图片加载失败即使短标可见也不得验收通过。
4. **检查展示。** 在现有容器内看主体占比、透明边缘、圆形是否完整、对比度和辨识度。新旧对照使用同一页面、同一样本、同一视口。若共用 CSS 不适合新图，先确认最小修正位置及影响，不追加全站覆盖规则。
5. **扩展整批。** 接入该联赛剩余16或14枚，记录逐枚结果；不顺手更换另一联赛。两套 ID 都要解析到同一资源。
6. **整批验收。** 对应20或18枚逐枚渲染检查，代表页面真实点击；生成真正的退休 PNG 并目视，完成第 6 节检查。通过后更新台账、问题和下一动作。

## 6. 验收标准与适量验证

### 6.1 本轮全部76枚必须检查

- 文件和俱乐部名称正确，canonical/workbook ID 一致，无资源串队或重复记录；新图确实加载成功。
- 每枚至少看 24、32、48、96 px 和原始比例的对照图；这些是对照尺寸，实际页面另按现有 CSS 验证，不改 UI 去迎合测试尺寸。
- 主体不被切掉、压扁、拉长、盖住；透明区域没有意外底板。小尺寸可辨识主符号，不要求细小装饰在 24 px 完整可读。
- 网络资源、字体和 SVG 特性在正式显示与导出中可用。优化体积以不损害成品为前提，不硬设每图必须小于某个字节数。
- 逐枚状态：通过／需技术适配／需设计师调整；记录具体原因。不得用一张大拼图未放大目视来代替逐枚检查。
