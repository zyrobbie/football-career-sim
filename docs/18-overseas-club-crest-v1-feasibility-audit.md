# 海外 334 家原创队徽 V1 可行性审计

审计日期：2026-08-27<br>
仓库基线：`2a932f7`（`origin/main`）<br>
阶段：`V7-B1 / PRODUCT_APPROVED`<br>
结论：**8 枚意甲原创圆形队徽样板已获用户视觉确认；统一圆形体系、固定色板和同色模板图腾差异成立。样板仍是资产与设计基线，尚未接入运行时。**

## 1. 用户提出的简化口径

1. 海外 334 家俱乐部统一使用圆形足球队徽外框；
2. 主副色不再逐队重新取证，直接参考已经上线的 14 套俱乐部视觉模板；
3. 核心视觉优先采用俱乐部长期身份符号，例如蛇、魔鬼、鹰、狼；
4. 缺少可靠俱乐部符号时，使用俱乐部所在城市的独特建筑、地理或文化符号；
5. 所有成品均为本地原创 SVG，不使用现实队徽文件。

这套口径显著降低了外形与配色成本；剩余主要工作不再是“画什么形状、用什么色”，而是为 334 家逐一确认**什么核心图腾既准确、可识别，又不会直接复制现实俱乐部标志**。

## 2. 数量与现有基础

- 运行时目录：366 家俱乐部、19 个联赛；
- 已完成：中国虚构俱乐部 32 家、32 枚本地原创 SVG；
- 本项目：海外现实身份俱乐部 334 家，分布于 17 个海外联赛；
- 已上线主题：14 套标准模板，366 家均已静态归类；
- 当前队徽清单：40 条，其中 32 条为可渲染原创资产，8 条为 `assetPath: null` 的现实身份参考记录；
- 当前 `ClubCrest` 已支持懒加载、加载失败短标回退；退役 PNG 已支持将队徽图片栅格化。

因此，新增海外原创队徽不需要重写组件或导出系统。技术工作主要是扩展资产、清单、校验和审核数据。

## 3. 可行性结论

### 3.1 技术可行

- 334 个 `128×128` 的精简 SVG 属于可控静态资产规模；
- 静态文件不会全部进入主 JavaScript 包；正式页面只会加载当前可见的少量队徽；
- canonical ID、workbook 兼容 ID、短标回退与退休导出链路均可沿用；
- 现有 32／56／128px Sharp 栅格化、安全扫描、正式页面与退休 PNG QA 可以复用。

### 3.2 设计可行，但不能直接开画 334 枚

统一圆形外框是合理的足球队徽语言，也能显著提升整体一致性。差异化必须集中在圆内：

- 主图腾的题材；
- 主图腾的姿态与视角；
- 正负形关系；
- 一项克制的城市辅助线索；
- 内环、分区、切割或留白构图。

同为鹰、狼、狮子或魔鬼并不构成问题，但不能出现“换颜色的同一只动物”。重复题材必须拥有不同姿态、构图和辅助线索。

### 3.3 资料工作是关键路径

“吉祥物优先”需要改成更准确的**俱乐部长期身份符号优先**。用户示例中：

- 有的是俱乐部长期动物／神话符号；
- 有的是历史昵称或身份叙事；
- 有的是城市符号；
- 不一定都是正式注册的吉祥物角色。

每家俱乐部必须在绘制前归入以下一种来源类型：

| 类型 | 含义 | 优先级 |
| --- | --- | --- |
| `CLUB_RECOGNIZED_SYMBOL` | 俱乐部长期公开使用的动物、神话、人物或身份符号 | 最高 |
| `OFFICIAL_MASCOT` | 俱乐部公开确认的正式吉祥物，但不得照搬角色造型 | 高 |
| `CLUB_NICKNAME` | 有可靠俱乐部来源支撑的长期昵称 | 中 |
| `CITY_CULTURE` | 城市建筑、地貌、产业、历史或文化符号 | 中 |
| `GENERIC_FALLBACK` | 无可靠专属线索时的通用题材，必须单独产品审核 | 最低 |

公开官方资料已能证明这一路径对一部分俱乐部成立：国际米兰官网的队徽历史明确记录蛇；AC 米兰官方历史以“魔鬼”定义创立身份；拉齐奥官方队徽史解释鹰的传统；罗马官网则把狼头称为俱乐部标志。它们证明方法可用，但不能代替对其余 330 家逐一核对。

## 4. 配色方案

不再为 334 家重新寻找精确官方色值。每家继续使用现有 `canonicalClubId → templateKey` 归类，并由 14 套主题派生固定队徽色板：

```text
templateKey → crestPrimary + crestSecondary + crestNeutral + crestOutline
```

注意：队徽色板不能机械照抄 UI 的全部 Token。例如 `BLUE_BLACK` 的 UI 强调色包含金色，但队徽主体应保持蓝＋近黑，金／米白只作为小面积识别或描边。14 套队徽色板应在首个视觉样板批次前一次冻结，后续不允许球队级颜色 override。

### 4.1 圆形徽章颜色层级（长期规则）

所有海外圆形队徽统一使用以下由外至内的层级：

1. `field`：内部圆形底色；
2. `ring`：8—10 单位宽、且必须与 `field` 异色的外环；
3. `separator`：仅当 `ring` 与 `field` 对比不足 3:1 时，位于两者之间约 2 单位宽的米白／浅色细分隔线；
4. `motif`：与 `field` 达到至少 4.5:1 对比度的核心图腾；
5. `motifAccent`：非必要的小面积辅助色，例如眼睛、火焰、风带或波纹。

外部仍保留透明安全区；不允许以多层装饰圆环制造复杂度。`ring` 与 `field` 不得相同；同一固定 palette 可以在不同俱乐部之间交换 `field` 与 `ring` 的角色，例如蓝底黑环或黑底蓝环，但不得新增球队级色值。深色 field 的主图腾优先使用白色／米白，浅色 field 的主图腾优先使用深色；低对比俱乐部色只能作为 `motifAccent`，不能承担 32px 的核心识别。

当动物全身在 32px 无法成立时，应优先改为原创头部图腾。语义识别优先于“尽可能多使用俱乐部色”。

## 5. 必须锁定的原创边界

每枚海外队徽必须满足：

- 圆形外框，`viewBox="0 0 128 128"`；
- 不使用俱乐部名称、缩写、成立年份、赞助商或赛事文字；
- 不复制现实队徽的字母组合、官方盾形、分区比例、现成吉祥物角色造型或完整构图；
- 动物、神话人物与城市符号必须重新设计姿态、线条和负形；
- 不直接描摹城市徽章、官方印章或现实队徽中的注册图形；
- 只使用本地 SVG path／基本几何，不含 `<text>`、脚本、外链、嵌入位图、外部字体或 filter；
- 32px 必须仍能识别主图腾，不能靠 128px 才看懂的细节成立。

这会显著降低“直接使用真实 Logo 文件”的风险，但不会让现实俱乐部名称、配色与高度关联符号产生的品牌风险归零。正式商业化或大规模分发前仍应单独做法律审核；本审计只判断产品和工程可行性。

## 6. 数据与工程结构

### 6.1 先建立概念清单

新增单一事实来源：

`docs/data/overseas-club-crest-concepts-v1.csv`

至少包含：

```text
canonicalClubId
workbookId
displayName
league
templateKey
motifSourceType
primaryMotif
secondaryMotif
compositionKey
sourceUrl
rationale
reviewStatus
assetPath
```

`primaryMotif` 不要求 334 个词面全部唯一；`compositionKey` 必须用于发现“同题材、同姿态、同构图”的实际碰撞。

### 6.2 不手写 334 条冗长运行时对象

概念 CSV 经检查后生成紧凑的 canonical ID → SVG 文件映射。运行时清单仍只认本地原创资产；当前 8 条 `assetPath: null` 的现实参考记录在对应原创资产接入时应迁移其来源说明，不能与原创记录形成重复 canonical ID。

生成器只负责映射和校验，不能自动决定图腾、自动画动物或批量换色。

## 7. 推荐执行顺序

### V7-A1：意甲 20 家概念清单

已完成只读研究，不画 SVG。20 条唯一的 canonical／workbook 兼容 ID、当前主题模板、来源类型、主／辅图腾、构图 key、来源链接和审核状态均记录于 [概念清单 CSV](data/overseas-club-crest-concepts-v1.csv)。

本批来源分布：`CLUB_RECOGNIZED_SYMBOL` 5、`OFFICIAL_MASCOT` 1、`CLUB_NICKNAME` 2、`CITY_CULTURE` 12；`NEEDS_REVIEW` 0。这里的“来源”用于核对图腾题材，不授权复制现实队徽、字标、官方盾形、成立年份或完整构图。

题材／构图碰撞复核：

- 动物身份：蛇（向上 S 形负形）、魔鬼（斜向火痕）、斑马（侧颈条纹）、鹰（俯冲）、狼（回望）、公牛（腾跃）、金丝雀（短翼侧飞）、狮鹫（攀升）均分配了不同姿态、重心与辅助线索；不得用换色复用同一动物 path。
- 城市建筑／地貌：科莫为湖山分叉，博洛尼亚为不等高双塔，佛罗伦萨为三孔桥，卡利亚里为石塔港湾，莱切为巴洛克门拱，蒙扎为三段拱冠，帕尔马为八角洗礼堂，萨索洛为瓷砖，乌迪内斯为城堡山顶，威尼斯为贡多拉船首；桥、塔、拱与水线均不共享相同 `compositionKey`。
- 同色模板并不等于同一队徽。`BLUE_BLACK` 的国际米兰／亚特兰大分别采用蛇与女神；`BLUE_RED` 的博洛尼亚／卡利亚里／热那亚分别采用双塔、石塔港湾、狮鹫灯塔。

拟进入 V7-B1 的 8 枚样板固定为：国际米兰、AC米兰、拉齐奥、罗马、亚特兰大，以及三个城市文化型样板科莫、博洛尼亚、威尼斯。其余 12 家只完成概念，尚不得绘制。

返修后的审核决定：亚特兰大不使用现行队徽特有的五分头部线条；罗马不使用母狼哺育双子的结构；科莫改用市政府稳定来源；那不勒斯仅将官方公园资料用于维苏威，海湾弧明确是原创辅助。

验收：意甲 20 家均有来源类型、主图腾、构图方向、来源链接和碰撞检查；已获产品审核，可进入 8 枚样板。

### V7-B1：8 枚意甲视觉样板

已制作的候选样板为国际米兰、AC米兰、拉齐奥、罗马、亚特兰大、科莫、博洛尼亚、威尼斯，对应文件均只存在于本地资产目录，尚未写入 `clubCrests.ts` 或运行时 manifest。14 套固定色板记录于 [队徽色板 CSV](data/club-crest-palettes-v1.csv)；每种颜色均取自现有正式主题 Token，不允许球队级覆盖。

R1 将 8 枚候选统一为“透明安全区 → 异色 `ring` → `field` → 高对比 `motif` → 可选小面积 `motifAccent`”。国际米兰、亚特兰大与博洛尼亚因 `ring`／`field` 对比不足加入细浅色 `separator`；威尼斯由纵向 S 形改为横向贡多拉船身加竖向船首铁饰。AC米兰与罗马随后因小尺寸辨识不足继续返工：最终 AC米兰采用正面双角、怒目、獠牙和尖胡的原创魔鬼脸；罗马采用金色右向咆哮狼头，以长吻、张口、犬齿和后颈毛束建立识别。两枚均未直接描摹现实队徽或用户提供的图库参考。

本批目的不是优先完成名门，而是验证：

- 同为圆形能否保持明显差异；
- 动物／神话／人物／建筑四类是否都能在 32px 成立；
- 14 套主题派生的队徽色板是否与正式 UI 协调；
- 是否出现对现实队徽构图的过度接近。

本批防撞结论：国际米兰／亚特兰大在相同 `BLUE_BLACK` 色板中分别为上扬蛇身与前行女神，拉齐奥／科莫在相同 `SKY_BLUE` 色板中分别为俯冲鹰与横向湖山，AC米兰／罗马分别采用正面魔鬼脸与右向张口狼头；科莫、博洛尼亚、威尼斯分别为自然景观、建筑与器物构图。

本批不进行运行时接入、正式页面或退役 PNG 验收。用户已确认最终 8 枚样板，可作为后续批次的圆形结构、配色层级与 32px 辨识基线。

## 8. 每批固定验收门槛

1. 14 个 canonical ID、文件名与资产路径唯一；
2. 14 个 SVG 均能由 Sharp 解析并栅格化为 32／56／128px；
3. 圆形外边界、安全区、最小线宽和颜色白名单通过；
4. 无文字、外链、脚本、嵌入位图、外部字体或 filter；
5. `primaryMotif`、`compositionKey` 和来源记录齐全；
6. 同题材队徽完成姿态／构图碰撞人工复核；
7. `ClubCrest` 显示 asset 而非 fallback；
8. 退役导出栅格化链路定向测试通过；
9. 生成 14 枚同屏审核图，用户确认后才能锁定；
10. 不修改主题、存档、玩法、荣誉或俱乐部参数。

## 9. 停止条件

出现以下任一情况立即停在当前俱乐部或当前批次，不猜画：

- 无法确定俱乐部长期身份符号，城市线索也存在多种冲突；
- 来源只有搜索缩略图、球迷二创或无出处图片；
- 新图必须依赖现实队徽字标／特定构图才能被识别；
- 32px 无法区分同批其他队徽；
- 批量脚本开始替代产品判断或原创绘制。

## 10. 最终判断

**可以做，而且现在比此前更可执行。**

统一圆形、复用 14 套已上线配色，足以把 334 枚从“不可控的自由设计项目”缩减为“逐队研究核心图腾、在稳定徽章系统中原创表达”的长期资产工程。真正的前置门槛不是再做技术原型，而是先完成意甲 20 家概念清单和 8 枚视觉样板；在这两步通过之前，不应一次性启动全部 334 枚绘制。
